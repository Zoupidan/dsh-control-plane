## 1. 核心要求（硬约束，零容忍，不可协商）

| # | 约束 | 判定标准 |
|---|---|---|
| C1 | **唯一通信通道是 WorkBuddy 桌面端进程（CDP + 内部自动化队列）** | 一切操作经桌面端执行，不得绕过桌面端直接操作 |
| C2 | **零 CLI**：插件任何运行路径——正常流、错误回退分支、探测逻辑——严禁拉起 WorkBuddy CLI（workbuddy.exe 命令行方式）、CodeBuddy Launcher、或**任何显隐 Shell/控制台进程** | 仓库红线 `tools/ci/check-no-process-exec.mjs` + `check-no-exec-probe.mjs` 必须 PASS；且运行态不得有 pwsh/cmd/netstat/tasklist 等进程出口 |
| C3 | **零反代伪装**：严禁 HTTP 反向代理、本地端口转发（如 127.0.0.1:18488）、中间人通道 | 通信必须是直接、真实的桌面端 IPC（wbipc 命名管道 / CDP 9222） |
| C4 | **任务下发、会话复用（session map / resume / direct ignition 点火）绝不碰 CLI** | 三条链逐跳零 spawn，只落 CDP 或桌面端 SQLite 自动化队列 |
| C5 | **运行时不得出现任何 Shell 命令窗口**（用户明确禁止可见控制台） | 闪窗根因已根治（见 §3.1），后续任何改动不得回退该补丁 |

**合法架构（唯一允许的形态）**：
- 下发/追发/点火 → CDP `ws://127.0.0.1:9222`（`src/host/followup/dispatcher.js`）
- 内部自动化队列 → 桌面端 SQLite `automations` 表（`src/host/gateway/automation.js`）
- 登录态/账单 → wbipc 命名管道 `\\.\pipe\wbipc-*` 由桌面端代发（`src/host/gateway/wbipc.js`）
